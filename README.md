# mycloud-infra

Terraform for my personal Azure portfolio. Each project gets its own resource
group, its own folder under `projects/`, and its own remote state file — so a
mistake in one project can never touch another.

Everything targets Azure **free tiers**: Static Web Apps (Free), App Service
(F1), and the Azure SQL Database free offer (serverless, auto-pauses when the
monthly quota is used up). Target monthly cost: **$0**.

## Layout

```
projects/
  tydee/        Envelope-budgeting app — RG + App Service F1 + SWA Free + SQL free offer
modules/        Shared modules (extracted once a pattern repeats across projects)
```

## Environments

Names carry an environment suffix (`stg`/`prd`, e.g. `rg-tydee-stg`), and the
environment is a hardcoded local — the folder decides the environment, so prd
values can never be applied against stg state. Environments are deliberately
**separate copies, not a shared module**: they're expected to diverge (prd will
use paid SKUs), and full isolation beats DRY for two environments. Today only
`stg` exists; a `prd` folder gets created if a project ever needs it.

## Remote state

State lives in an Azure Storage account (`stmycloudtfstate` /container
`tfstate`), created manually once — Terraform can't store its state in a
storage account it hasn't created yet. Each project uses its own `key`
(e.g. `tydee.tfstate`). Auth is Entra ID (`use_azuread_auth = true`), so no
storage keys are needed.

## Usage

```bash
cd projects/tydee
cp terraform.tfvars.example terraform.tfvars   # fill in subscription_id
az login                                        # personal tenant
terraform init
terraform plan
terraform apply
```

Secrets never live in this repo: real `*.tfvars` and all state files are
gitignored; the SQL password is generated by `random_password` and lives only
in the remote state.
